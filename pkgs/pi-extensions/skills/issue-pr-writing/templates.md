# AIPR 文章テンプレート（Linear + GitHub PR）

文書種別を決め、該当する型をそのまま使う。見出しを増やさず、順序を変えず、空欄で提出しない。該当情報がない任意節には「なし」と理由を書く。

## Project summary

1 行、120 字以内で、何を実現する Project か（What）と対象読者が分かるように書く。

型: `[対象読者]が、[実現する状態・価値]を得られるようにする。`

## Project description

<!-- schema:project-description -->

```markdown
## 誰のために（Who）

[利用者、顧客、運用担当などの対象]

## 何を実現するか（What）

[完了後に対象者が得られる状態]

## なぜやるのか（Why）

[現状の問題と、解消する理由]

## 完了条件

- [ ] [観測できる状態と確認手段]

## スコープ外

- [今回扱わないこと]
```

見出しを増やさない。順序を変えない。プレースホルダーや空欄を残したまま提出しない。

## Issue title

「対象 + 変更 + 結果」を 1 句、40 字目安で書く。`AIPR-###` は Linear が付与するため含めない。

型: `[対象]の[変更]で[得られる結果]`

## Issue description

<!-- schema:issue-description -->

```markdown
## 概要

[何をするのか、なぜやるのかを 1〜3 行で書く]

## 背景・現状

[確認済みの事実、推論、未確認事項を区別して書く]

## やること

- [今回行うこと]

## やらないこと（スコープ外）

- [今回行わないこと]

## 完了条件

- [ ] [完了時に観測できる状態と確認手段]

## 参考情報

- [関連資料や確認事項。なければ「なし」と書く]
```

見出しを増やさない。順序を変えない。プレースホルダーや空欄を残したまま提出しない。

## コメント・ステータス更新

<!-- schema:comment -->

```markdown
現状: [未マージ / main マージ済み / Stg 反映済み / Prd 反映済み / 顧客告知済みのどこか]

根拠:
- 事実: [確認できた結果と確認手段]
- 推論: [事実から推測する内容と、その機構]
- 未確認: [まだ確認できていない内容]

次の一手: [担当または確認先と、次に行うこと]

確認事項: [誰に何を確認するか。なければ「なし」]
```

項目を増やさない。順序を変えない。空欄で提出せず、該当しない根拠には「なし」と理由を書く。

## PR 本文

<!-- schema:pr-body -->

```markdown
## 概要

[この PR が何を変更するかを 1〜3 行で書く]

## 背景

[なぜこの変更が必要か。確認済みの事実と推論を区別して書く]

## 変更内容

- [git diff から確認できる変更点を列挙する]

## 変更しないこと

- [スコープ外にした変更や、意図的に手を付けなかった箇所]

## 検証

- [実際に実行したコマンドと結果。未実行のものは「未確認」と書く]

## 影響範囲・リスク

- [Web / Core / Patent DB のどの責務、Stg / Prd のどの環境に影響しうるか]

## レビューしてほしい点

- [対象ファイル・関数・観点など、具体的にレビューしてほしい箇所]

## 関連情報

- [関連 Linear Issue、参考資料。なければ「なし」]
```

見出しを増やさない。順序を変えない。プレースホルダーや空欄を残したまま提出しない。各節の主張は git diff、実際の検証出力、関連 Issue、または与えられた context のいずれかに接地する。PR タイトルはこのテンプレートの対象外。
